# Generic ATS send safety

- **Dry run is read-only.** The service loads the page in a fresh, headless browser profile without candidate data. Before inspecting the form or calling the planner, the engine takes the context offline and denies routed requests. No values, files, credentials, choices, or clicks reach the page. Inspection can report missing inputs; otherwise it reports the form as untested. It does not dismiss banners, open a form behind a button, test JavaScript widgets, or validate a multistep flow. Browser routing alone is not treated as a complete egress sandbox.
- **Generic automated sends are disabled.** UI events can send data before the nominal submit button; a changed form, validation banner, or attachment state cannot prove otherwise. Neither an approved revision nor the legacy callback interface enables dispatch. The supervised extension below allows the operator, not the engine, to submit. No production ATS adapter is enabled.
- **Ambiguity stays durable.** Any unreleased reservation, navigation or final dispatch marker, or engine report of a possible send retains a hold for operator verification. Generic receipt text and a planner's `submitted` status cannot update the application or job as sent. Existing operator settlement is unchanged.

To enable a send for a particular ATS, a vetted adapter must establish which operations can transmit data and reserve the attempt durably before any such operation. It must recheck current approval and policy at that boundary, bind the current revision and exact PDF bytes and verified destination to the reservation, and authenticate and correlate the server receipt to the same attempt. Retry is unsafe without conclusive non-delivery or a verified idempotency mechanism. Page text, form structure, and URL changes are not receipts.

Legacy engine integration tests that require generic dry-run autofill or live generic dispatch assert behavior that is intentionally disabled; they are not evidence of an adapter-backed flow.

## Supervised sending extension

Generic unattended dispatch is still disabled. A single explicit supervised launch is allowed on an unadapted site after human approval of the exact eligible revision. CLI `big-penalty apply supervised ID` and the application page explain that **typing, upload and blur events can transmit candidate data before any submit click**. This risk is accepted only for this individual, human-approved, attended flow. Dry inspection remains offline before form inspection and does not interact with controls.

1. Match the displayed revision and destination, re-check approval, eligibility and policy, then reserve the attempt before opening a fresh, visible browser. Store the revision, exact PDF SHA-256 and verified URL/host; upload only the already-hashed byte buffer.
2. Inspect with the existing planner and verifier, and re-check the live destination, binding, scoped options and consent guards before every autofill action. Autofill is limited to native text and select fields and native CV inputs. No automated job-site button clicks, field-opener clicks or account actions occur. The operator handles navigation, custom widgets, consent and the final click. Missing questions are captured even when the operator must finish by hand.
3. Hand the open page to the operator with French instructions. Close or crash leaves the reserved attempt in **À vérifier**. Page text never settles it. After checking the company's site, use **Envoyée** or **Pas envoyée** on the attempt page. In doubt, leave it held. There is no automatic retry.

Limits: checking DOM destinations is not a browser network sandbox. A same-origin form may run scripts or delegate to another server, and a malicious or changing page can defeat ordinary UI expectations. The operator may need to finish multi-page forms manually. The browser can disappear after transmitting data, so even failures with no recorded click are held. The fake adapter exercises the shared contract on a local fixture; no production ATS is configured or validated. See `docs/ats-adapters.md`.
