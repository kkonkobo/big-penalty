# ATS adapter contract

The production registry is empty. Adapters default to supervised: platform-specific planning and fill, with navigation and the final click left to the human. `apply send`, the selected web batch and the daily pass may dispatch only through an unattended adapter with an explicit tenant allowlist entry. Keep every other offer in the supervised queue.

## Implementing an adapter

Implement `Adapter` in `src/jobhunt/apply/adapters.py`:

```python
name: str
capability: Literal["supervised", "unattended"]
boundaries: Mapping[Boundary, BoundaryPolicy]
retry_rule: Literal["never"]

def matches(self, url: str, dom_markers: frozenset[str]) -> float: ...
def resolve(self, url: str, dom_markers: frozenset[str]) -> Requisition | None: ...
async def supervise(self, request: Dispatch, fill: Callable[[Planner], Awaitable[RunResult]]) -> RunResult: ...
async def dispatch(self, request: Dispatch, gate: WriteGate) -> object: ...
async def verify_receipt(self, attempt: Attempt, *, evidence: object = None) -> Receipt: ...
```

1. Make `matches` and `resolve` pure and local. Validate exact postings, tenant and path; return `Requisition(tenant, requisition_id, write_origins=(), endpoints=())` only when confident. `tenant` is a canonical employer-tenant identifier, not a host, branding name or source row. Alias URLs for one requisition must resolve to the same identity. Recognition uses the registered exact host, optional `origin_ats` and confidence ≥0.9; weak/missing evidence does not authorize unattended dispatch. The service currently passes no preloaded DOM markers; the parameter is available to resolver callers and future verified origin evidence. Do not change `origin.py` as part of adding an adapter.
2. Register reviewed code with `registry.register(adapter, host=..., origin_ats=...)`. For unattended promotion require both `capability="unattended"` and `unattended_tenants={canonical_tenant: demonstrated_receipt_type}`. This mapping is a code-review attestation to a positive receipt from supervised pilots, not a claim inferred from a status code. There is no enrolled production tenant. The service requires a canonical requisition for unattended mode; without one the supervised reservation falls back to the local job ID. The durable duplicate key is `(profile, canonical tenant, requisition)` and remains occupied while delivery is possible or confirmed, even across different job rows.
3. Declare `account_creation`, `login_otp`, `cv_upload_parse`, `draft_write` (including autosave and persisting Next steps), and `final_submit` as `auto`, `pause_for_human` or `forbidden`; omitted boundaries are forbidden. Supervised adapters supply a planner to `fill(planner)` once, not an executable callback or a browser handle. The shared engine runs its live field/choice/consent guards and rechecks approval, policy, PDF, reservation and the adapter before each mutation, including rollback. It provides no automated click primitive. For unattended HTTP, `await gate.perform(boundary, target_url, attach_pdf=False)` owns the transport: it can POST only an empty body or the bound PDF at an allowed upload or final boundary. Return `endpoints=(("final_submit", "https://careers.example.test/{tenant}/jobs/{requisition}/apply"),)` from `resolve()` for each brokered boundary. The broker substitutes URL-escaped `{tenant}` and `{requisition}` from the attempt, requires both placeholders, and compares the exact absolute URL before network access. An omitted endpoint, a different path on the same origin, and any POST redirect are refused. A platform needing additional write operations must add a reviewed, typed transport operation rather than bypass this gate. No networking or data staging during resolver/setup. Stop on CAPTCHA, OTP, 403/429, unknown answers/consent, refused redirect or missing receipt. Extra origins must be exact, explicitly declared same-tenant recipients. Initial supervised GET/HEAD navigations may follow up to five individually approved hops before autofill; write redirects are never replayed.
4. `verify_receipt` returns `Receipt(attempt, outcome, kind, reference="", observed_nonce="", observed_requisition="")`. Outcomes: `confirmed`, `not_sent`, `uncertain`; types: `first_party_confirmation`, `candidate_home_listing`, `correlated_email`, `none`. Both terminal outcomes must match the tenant's attested kind and carry a nonempty reference and both observed correlation values from authenticated evidence; never populate them from the request alone. Only affirmative proof can confirm or rule out delivery; an absent listing, HTTP 200, successful upload, generic redirect or disappearing Submit button is not proof. Keep raw evidence transient. Persist only a minimized attempt record (origin/recognized posting ID and full destination digest instead of opaque path), receipt type, time and sanitized outcome; never persist OTPs, tracking links or raw responses. `Attempt.url` remains the vetted URL in memory. With no immediate evidence, `service.reconcile_attempt(run_id)` calls the same hook using existing authorized read-only evidence; it never calls `dispatch`. If reconciliation requires authentication, stop for the human rather than initiating a new write or OTP. Unknown or mismatched results remain held; valid `not_sent` permits only a new manual launch after approval. Old holds without the new URL digest remain available to the human settlement workflow, not automatic reconciliation.
5. `retry_rule="never"`: disable HTTP/client retries inside the adapter. Any future automatic resubmission would need a reviewed idempotency or proven non-delivery contract. Use the provided bytes, never reread a PDF path. Extend the shared approval and binding if additional candidate inputs need to be passed to a real adapter.

Add a synthetic loopback fixture factory to `tests/test_ats_adapter_contract.py`. Cover verified delivery, page text alone, mismatched receipt, interruption, stale approval or destination and an absent registry entry. Assert that the first transmission observes the durable reservation with the same nonce, destination, revision and PDF digest. Add adapter-specific tests for confusing or spoofed receipts, changed destinations and any nontrivial transmission sequence. Never exercise the contract on a real ATS or with real applicant data.

The registry is a trusted code boundary, not a sandbox. Reviews must establish that the adapter obeys its declaration, uses the bound destination and authenticates receipt evidence; checking that a `Receipt` object matches the attempt is not a substitute for that review.
## Supervised fill-step API

- `await service.preview_fill_step(app_id: int, *, run_id: int | None = None) -> FillPreview` checks the active browser and reservation. `FillPreview` carries `token`, `run_id`, `application_id`, `company`, `title`, `reserved_url`, `page_url`, `warning`, and `requires_confirmation`. URLs shown to the operator omit opaque paths and secret-bearing parameters. The operator can inspect the full address in the supervised window itself.
- `await service.fill_step(app_id: int, token: str, *, run_id: int | None = None) -> RunResult` consumes that token once. The web action is **Remplir cette étape**; the CLI equivalent is `big-penalty apply fill-step APP_ID`, from a second terminal if the launch is in the CLI. Neither starts a browser, creates a reservation, nor clicks a site control. The token is bound to the attempt nonce, minimized current top-level URL and title/visible H1 digest. Generic sites open blank of candidate data and need this confirmation on every pass. A generic confirmation also binds the document instance and expires on any main-frame navigation, including same-URL reloads and history changes. Generic fields are restricted to the top-level document and compatible form actions; other fields are manual. These checks do not replace or change the adapter resolver. A stale approval, reservation or PDF closes the window instead.
- Adapter signatures and dataclasses are unchanged. `supervise(request: Dispatch, fill: Callable[[Planner], Awaitable[RunResult]]) -> RunResult` may now be called multiple times, once per pass, with the same reserved request and a fresh one-use `fill(planner)` callback. The callback fills only the currently displayed step, without navigating. Do not retain or schedule it; return its result. The engine result takes precedence if the adapter returns a different result. The service may run the first pass on launch for a canonical requisition. With no canonical requisition, it waits for the generic confirmation.
- `supervised.require_posting(match: Match, attempt: Attempt, *urls: str) -> None` raises `ApplyError` if any URL cannot be vetted or does not resolve to the exact canonical `(tenant, requisition_id)` reserved for the attempt. The service checks the live top-level URL on entry and around planning, and additionally checks the target field's containing document URL and effective form action immediately before each mutation, including upload and rollback. `resolve(url, frozenset())` must recognize each step URL, form action and embedded form URL that belongs to that posting, not merely recognize the ATS domain. A missing form action falls back to the containing document URL. Fail closed when an endpoint or SPA route does not identify a requisition; do not infer it from the reserved URL. An identity refusal closes the browser and keeps the hold.
