# ATS adapter contract

Workday and SmartRecruiters can use the unattended browser for postings they resolve unambiguously. Supervised mode still leaves navigation, account entry and the final click to the operator. Setting `JOBHUNT_APPLY_AUTONOMOUS` to `0`, `false`, `no`, or `off`, or tripping the shared per-host circuit breaker, disables unattended dispatch. An unresolved receipt still holds the individual application; switching modes does not release it.

## Implementing an adapter

Implement `Adapter` in `src/jobhunt/apply/adapters.py`:

```python
name: str
capability: Literal["supervised", "unattended"]
boundaries: Mapping[Boundary, BoundaryPolicy]
retry_rule: Literal["never"]

def matches(self, url: str, dom_markers: frozenset[str]) -> float: ...
def resolve(self, url: str, dom_markers: frozenset[str]) -> Requisition | None: ...
async def supervise(self, request: Dispatch, fill: Callable[[Planner], Awaitable[RunResult]]) -> RunResult: ...
async def dispatch(self, request: Dispatch, gate: WriteGate) -> object: ...
async def verify_receipt(self, attempt: Attempt, *, evidence: object = None) -> Receipt: ...
```

1. Make `matches` and `resolve` pure and local. Validate exact postings, tenant and path; return `Requisition(tenant, requisition_id, write_origins=(), endpoints=(), read_origins=())` only when confident. `tenant` is a canonical employer-tenant identifier, not a host, branding name or source row. Alias URLs for one requisition must resolve to the same identity. Recognition uses a code-registered host or domain, optional `origin_ats` and confidence ≥0.9; weak/missing evidence does not authorize unattended dispatch. The service does not assume DOM markers. Do not change `origin.py` as part of adding an adapter.
2. Register reviewed browser adapters with `registry.register(adapter, host=..., auto_enroll=receipt_kind, supervised_receipt_kind=...)`; add `include_subdomains=True` only for platform domains validated by the resolver. Auto-enrollment also requires `browser_enrollable(url)` and a canonical requisition. The legacy fixed-HTTP broker still requires an explicit `unattended_tenants` mapping. The durable duplicate key is `(profile, canonical tenant, requisition)` and remains occupied while delivery is possible or confirmed, even across different job rows.
3. Declare `account_creation`, `login_otp`, `cv_upload_parse`, `draft_write` (including autosave and persisting Next steps), and `final_submit` as `auto`, `pause_for_human` or `forbidden`; omitted boundaries are forbidden. Supervised adapters supply a planner to `fill(planner)` once, not an executable callback or a browser handle. The shared engine runs its live field/choice/consent guards and rechecks approval, policy, PDF, reservation and the adapter before each mutation, including rollback. It provides no automated click primitive. For unattended HTTP, `await gate.perform(boundary, target_url, attach_pdf=False)` owns the transport: it can POST only an empty body or the bound PDF at an allowed upload or final boundary. Return `endpoints=(("final_submit", "https://careers.example.test/{tenant}/jobs/{requisition}/apply"),)` from `resolve()` for each brokered boundary. The broker substitutes URL-escaped `{tenant}` and `{requisition}` from the attempt, requires both placeholders, and compares the exact absolute URL before network access. An omitted endpoint, a different path on the same origin, and any POST redirect are refused. A platform needing additional write operations must add a reviewed, typed transport operation rather than bypass this gate. No networking or data staging during resolver/setup. Stop on CAPTCHA, OTP, 403/429, unknown answers/consent, refused redirect or missing receipt. Extra origins must be exact, explicitly declared same-tenant recipients. Initial supervised GET/HEAD navigations may follow up to five individually approved hops before autofill; write redirects are never replayed.
4. `verify_receipt` returns `Receipt(attempt, outcome, kind, reference="", observed_nonce="", observed_requisition="")`. Outcomes: `confirmed`, `not_sent`, `uncertain`; types: `first_party_confirmation`, `candidate_home_listing`, `correlated_email`, `none`. Both terminal outcomes must match the tenant's attested kind and carry a nonempty reference and both observed correlation values from authenticated evidence; never populate them from the request alone. Only affirmative proof can confirm or rule out delivery; an absent listing, HTTP 200, successful upload, generic redirect or disappearing Submit button is not proof. Keep raw evidence transient. Persist only a minimized attempt record (origin/recognized posting ID and full destination digest instead of opaque path), receipt type, time and sanitized outcome; never persist OTPs, tracking links or raw responses. `Attempt.url` remains the vetted URL in memory. With no immediate evidence, `service.reconcile_attempt(run_id)` calls the same hook using existing authorized read-only evidence; it never calls `dispatch`. If reconciliation requires authentication, stop for the human rather than initiating a new write or OTP. Unknown or mismatched results remain held; valid `not_sent` permits only a new manual launch after approval. Old holds without the new URL digest remain available to the human settlement workflow, not automatic reconciliation.
5. `retry_rule="never"`: disable HTTP/client retries inside the adapter. Any future automatic resubmission would need a reviewed idempotency or proven non-delivery contract. Use the provided bytes, never reread a PDF path. Extend the shared approval and binding if additional candidate inputs need to be passed to a real adapter.

Add a synthetic loopback fixture factory to `tests/test_ats_adapter_contract.py`. Cover verified delivery, page text alone, mismatched receipt, interruption, stale approval or destination and an absent registry entry. Assert that the first transmission observes the durable reservation with the same nonce, destination, revision and PDF digest. Add adapter-specific tests for confusing or spoofed receipts, changed destinations and any nontrivial transmission sequence. Never exercise the contract on a real ATS or with real applicant data.

The registry is a trusted code boundary, not a sandbox. Reviews must establish that the adapter obeys its declaration, uses the bound destination and authenticates receipt evidence; checking that a `Receipt` object matches the attempt is not a substitute for that review.

### Optional race and ethnicity disclosure

`race_ethnicity` is the optional standing answer exposed through `FactSheet.get("race_ethnicity")` and the approved adapter dispatch facts. It is not inferred from a name, nationality, or CV. For profile 1, the coordinator should set the requested value (`Black`) in **Réponses aux formulaires → À compléter une fois → Origine ethnique**; there is no automatic seed. Clear the field to withdraw the standing answer. Use the stored value only on an identified race or ethnicity question with a unique equivalent enabled option in the live, scoped option set. Otherwise use an explicit opt-out if present, or leave a required question for manual input. Do not use this fact to answer other demographic questions.

## Supervised fill-step API

- `await service.preview_fill_step(app_id: int, *, run_id: int | None = None) -> FillPreview` checks the active browser and reservation. `FillPreview` carries `token`, `run_id`, `application_id`, `company`, `title`, `reserved_url`, `page_url`, `warning`, and `requires_confirmation`. URLs shown to the operator omit opaque paths and secret-bearing parameters. The operator can inspect the full address in the supervised window itself.
- `await service.fill_step(app_id: int, token: str, *, run_id: int | None = None) -> RunResult` consumes that token once. The web action is **Remplir cette étape**; the CLI equivalent is `big-penalty apply fill-step APP_ID`, from a second terminal if the launch is in the CLI. Neither starts a browser, creates a reservation, nor clicks a site control. The token is bound to the attempt nonce, minimized current top-level URL and title/visible H1 digest. Generic sites open blank of candidate data and need this confirmation on every pass. A generic confirmation also binds the document instance and expires on any main-frame navigation, including same-URL reloads and history changes. Generic fields are restricted to the top-level document and compatible form actions; other fields are manual. These checks do not replace or change the adapter resolver. A stale approval, reservation or PDF closes the window instead.
- Adapter signatures and dataclasses are unchanged. `supervise(request: Dispatch, fill: Callable[[Planner], Awaitable[RunResult]]) -> RunResult` may now be called multiple times, once per pass, with the same reserved request and a fresh one-use `fill(planner)` callback. The callback fills only the currently displayed step, without navigating. Do not retain or schedule it; return its result. The engine result takes precedence if the adapter returns a different result. The service may run the first pass on launch for a canonical requisition. With no canonical requisition, it waits for the generic confirmation.
- `supervised.require_posting(match: Match, attempt: Attempt, *urls: str) -> None` raises `ApplyError` if any URL cannot be vetted or does not resolve to the exact canonical `(tenant, requisition_id)` reserved for the attempt. The service checks the live top-level URL on entry and around planning, and additionally checks the target field's containing document URL and effective form action immediately before each mutation, including upload and rollback. `resolve(url, frozenset())` must recognize each step URL, form action and embedded form URL that belongs to that posting, not merely recognize the ATS domain. A missing form action falls back to the containing document URL. Fail closed when an endpoint or SPA route does not identify a requisition; do not infer it from the reserved URL. An identity refusal closes the browser and keeps the hold.

## Unattended building blocks

Generic autonomy is the fallback whenever `Registry.find()` returns no match or a match without tenant-attested `unattended` capability. For generic sends, a supervised match contributes only the canonical posting identity to the reservation and dedupe. Its fill, dispatch, receipt hooks and write origins are not used. A tenant-attested unattended match takes precedence, even if generic autonomy is enabled.

- **Submit:** `await unattended.click_once(target, *, recheck, timeout_ms)` is the one-click boundary used by the browser engine. Supply the exact `ElementHandle` and an async `recheck()` that validates the live form, posting and recipient, rechecks approval, revision, PDF and reservation, and durably marks the final click. It runs after the actionability reads, immediately before activation. `ClickUncertain` means the click may have fired: hold the attempt and never retry. This helper does not authorize writes or install a route guard; use it only in a service-owned, recipient-guarded browser. The current adapter `WriteGate.perform()` remains the fixed-endpoint HTTP broker and does not grant browser access. Supervised callbacks never get a click primitive.
- **Receipt:** `engine.confirmation_evidence(text: str) -> bool` recognizes affirmative received-application wording. `autonomous.confirmation_url(url: str, posting_url: str) -> bool` recognizes known same-origin confirmation paths with compatible posting IDs. `autonomous.confirmation_json(body: bytes) -> bool` recognizes a positive JSON result from a final write. These are signals, not proof by themselves. The generic browser requires 2xx on the single write admitted during the final click. It accepts JSON only from that exact fetch/XHR response and requires the form to be gone for document-based evidence. For an unattended adapter, use these signals inside `verify_receipt()` only with independent correlation to the attempt and requisition and the tenant's attested receipt kind. Never persist a confirmation page, URL, or JSON body as evidence.
- **Accounts:** `accounts.guarded_account_callbacks(email, accepts_host) -> (password, account_known)` provides host-scoped Keychain lookup or creation and an existing-account check. The generic browser plugs these into the engine's `run_application(..., password=..., account_known=...)` login/signup actions. `accepts_host(host)` must check the current verified recipient each time. These callbacks do not write to the page or authorize the account boundary; enforce that separately. Do not log the returned password or handle OTP values programmatically.
- **Handoff:** a browser flow can return `unattended.handoff_result("email" | "human")`. In adapter `dispatch()`, use `gate.stop("otp")` for verification and `gate.stop("captcha")` for CAPTCHA. Before final submit these become `needs_email` or `needs_human`, so the batch proceeds to the next application. This does not clear an adapter reservation or authorize a retry. After a possible final submit, missing or mismatched evidence stays **À vérifier**.

Each dispatch stores `RunResult.dispatch_diagnostics`: the last step (`0` means no form or broker step), a control category, the receipt kind (`none` when absent), and an engine-authored reason. For example, `final_submit / none / no_confirmation` means the flow reached submit, but found no positive receipt. These diagnostics contain only a bounded step number and allowlisted codes: no field names, page text, URLs, receipt references or credentials. They remain visible in the stored result when failed runs discard their page details.

### Browser adapter hooks

`browser_planner(attempt) -> Planner` proposes field actions and one step control. `browser_control(url, automation_id, label, role, final) -> Boundary | None` declares the exact controls and is checked again against the live element inside the click boundary. `browser_native_post(source, target, boundary) -> bool` restricts native submissions; scripted writes require an exact `Requisition.endpoints` template. `browser_continuation(url, previous_url) -> bool` recognizes a known change to a read-only step. `browser_receipt_url(attempt, url) -> bool` limits confirmation navigation; `await browser_receipt(attempt, page, receipt_url, positive_text, posting) -> ReceiptType` consumes the service's same-tab, guarded response evidence. It is never called before a successful final-write response. No planner has a browser handle.

- **Workday:** recognized `*.myworkdayjobs.com` career-site URLs and `*.myworkdaysite.com/recruiting/<tenant>/<site>/job/...` URLs, with known `/apply/<step>` suffixes. The live binding includes the host and career site; deduplication uses the origin resolver's employer tenant and requisition. The unattended planner prefers Apply Manually, uses the shared host-scoped account callbacks, and fills known fields through Review. It accepts a correlated confirmation or a unique submitted Candidate Home row linking to the same requisition. The supervised Candidate Home action remains an explicit operator attestation.
- **SmartRecruiters:** recognized first-party `/oneclick-ui/company/<tenant>/publication/<uuid>` URLs and declared apply/step suffixes. The guest flow never signs in or imports a profile. A numeric advert ID does not prove a publication UUID. The receipt requires positive same-tab confirmation correlated to the publication; bare JSON or a status code is not enough.
- Both keep the 12-step cap and reuse the shared disclosure, opt-out, and unattended no-guess policy. A receipt requires the final-write response and a correlated page without a remaining form or validation error; an ordinary next-step URL or draft is not confirmation. Supervised adapter fills can select the matching native disclosure option without accepting consent, advancing, or submitting. Unknown required facts stop for input; verification codes and CAPTCHA are never filled. Unrecognized controls, paths or POSTs stop rather than falling back to generic dispatch mid-flow. Synthetic fixtures do not establish coverage for undocumented live variants.
